# 输出格式

## 整体结构

```
# PRD 逻辑评审｜{文档名}

评审时间 {日期} · 检查项 {N} 项 · 发现问题 {M} 项（阻塞 {a} / 高风险 {b} / 建议 {c}）

## 结论速览
{2-3 句：文档整体自洽程度如何，最需要优先处理的是什么}

## A. 可追溯性
{逐条列出，或写「未发现问题」}

## B. 逻辑完整性
{逐条列出，或写「未发现问题」}

## C. 一致性
{逐条列出，或写「未发现问题」}

## D. 落地质量（附加项）
{仅当文档已包含这类内容时输出；完全没有则整段省略}

## E. 跨文档一致性
{逐条列出，每条附依据文档的标题、更新时间、链接；未检索到则写「未检索到相关线上文档」}

## 待确认
{信息不足、无法判定的疑点，只描述疑点不判错}

## 检索覆盖说明
- 检索关键词：{列出}
- 覆盖文档库：{列出}
- 命中文档：{N} 篇 → 剔除噪音后 {M} 篇
- 收敛为基准：{列出标题 + 更新时间，或写「无」}
- 未覆盖：{说明未能检索到的方向，或工具调用失败记录}
```

## 单条问题的写法

```
### [阻塞] {一句话概括问题}
- **位置**：{章节名 / 引用原句}
- **问题**：{具体表现，必要时列出冲突双方}
- **影响**：{会导致什么后果}
- **建议**：{具体可执行的修改方向}
```

## 严重度定义

| 级别 | 含义 |
|---|---|
| 阻塞 | 会导致开发无法实现，或按文档实现后与需求目标相悖 |
| 高风险 | 会导致返工、上线后出现用户可见问题，或不同人理解不一致 |
| 建议 | 表达不清、粒度不足、可读性问题，不影响正确落地 |

## 硬性要求

- 每条问题必须能定位到原文；定位不到的不输出
- 「建议」字段禁止出现「建议完善」「建议补充说明」这类空话
- 没有问题的维度写「未发现问题」，不得省略该维度
- 不为凑数量制造条目，问题数量少不是缺陷
- D 维度只检查文档已有内容，不产出缺失类条目
- E 维度每条结论必须附依据文档的标题、更新时间与链接；无法溯源的不输出
- E 维度的「检索覆盖说明」必须输出，不得省略，让用户能判断是否查全
- 输出中文

## 示例

### [阻塞] 筛选规则与搜索规则的命中优先级缺失

- **位置**：3.2 筛选逻辑 / 4.1 混合搜索
- **问题**：两处规则均可能作用于同一结果集，文档未定义二者同时生效时谁先执行
- **影响**：开发需自行拍板，两端实现可能不一致，结果集不可预期
- **建议**：明确二者互斥，或补充仲裁规则（如「筛选条件作为搜索的前置过滤」）

### [高风险] 背景痛点 P2「重复筛选成本高」无功能承接

- **位置**：2.1 需求背景
- **问题**：痛点已列出，但功能清单中无对应条目，目标章节亦未覆盖
- **影响**：需求提出但未落地，或在后续迭代中被遗漏
- **建议**：补充「筛选条件保存与复用」功能条目，或在范围声明中显式排除并说明原因

### [高风险] 「筛选器」与「过滤器」两个名称指代同一对象

- **位置**：3.2 筛选逻辑（用「筛选器」）/ 4.3 组件说明（用「过滤器」）
- **问题**：同一概念出现两种命名，文档未说明二者关系
- **影响**：开发可能按两个组件实现，或反复确认造成沟通成本
- **建议**：统一术语，并在文档开头增加术语表

### [阻塞] 筛选条件的多选能力与线上 [2.7.3] 版本相反

- **位置**：3.2 筛选逻辑
- **依据**：[2.7.3] 搜索页样式调整（更新于 2026-09-17）
  `http://note.4399doc.com/prd?note_id=2522a09e47b1a4d8701b208c&group_id=975189ff4d9aa1642cd7d1aa`
- **线上规则**：高级筛选项支持多条件组合，云文档类型为多选且含「所有类型」
- **新 PRD 规则**：筛选条件为单选
- **问题**：两处结论相反，新 PRD 未说明这是对线上规则的变更
- **影响**：开发无法判断以哪份为准，可能覆盖线上已有能力
- **建议**：明确标注是否变更线上规则；若为升级，补充与旧版本的兼容说明

## 结论速览的写法

结论速览只说三件事，不要复述后面的清单：

1. 整体自洽程度（可直接进入评审 / 需先补齐关键逻辑 / 存在阻断性冲突）
2. 最优先处理的问题（点名 1-2 条阻塞项）
3. 是否影响排期（有无需要产品补充才能开工的部分）
