# 跨文档比对：线上需求库检索与冲突检测

用于 E 维度。目标是把待评审 PRD 的功能规则，跟**线上已有需求文档**里的规则做比对，找出跨文档冲突。

## 核心原则

1. **时间必须最新** —— 线上功能规则会持续迭代，比对必须基于最新版本。任何结论都要标注所依据文档的更新时间。
2. **链接必须给全** —— 每条结论都附上依据文档的标题和链接；拿不到链接时只写标题，并提示用户自行查看。
3. **宁缺毋滥** —— 检索不到相关文档时明确写「未检索到」，不要用猜测填补，也不要拿无关文档凑数。

## 第 1 步：确定检索范围

### 1.1 提取检索关键词

从待评审 PRD 中提取 3-8 个功能关键词，覆盖四类：

| 类型 | 说明 | 示例 |
|---|---|---|
| 功能模块名 | 文档自述的功能名 | 高级筛选、混合搜索 |
| 关键对象名 | 功能作用的核心对象、字段 | 筛选条件、分享链接、文档路径 |
| 产品 / 平台名 | 所在产品线 | 精卫 |
| 关联动作 | 会改变状态的操作 | 保存、排序、跳转 |

关键词**逐个独立检索**后取并集。不要用长句组合检索，会漏召回。

### 1.2 确定文档库范围

先调用 `mcp__note__list-group` 获取文档库列表，按产品线收敛候选库：

- 优先使用该产品的**需求管理库**（如「精卫-需求管理」「精卫线上测试」）
- 其次考虑同产品的项目管理库
- 用检索结果中的 `group_name` 判断文档是否属于目标产品，不属于的直接剔除

不要跨产品线混用规则。不同产品的同名功能默认无关联。

## 第 2 步：检索

对每个关键词调用 `mcp__note__search-note`。合并结果后剔除以下噪音文档：

- 周报、月报、日报（标题含「周报」「月报」「日报」）
- 交接文档、会议纪要、会话总结
- 与目标功能无关的其他库内文档（按 `group_name` 判断）

保留文档的标准是：**标题或高亮内容中出现目标功能的关键概念，且属于目标产品线**。

## 第 3 步：版本收敛（关键步骤）

同一功能往往存在多篇文档或多个版本，必须收敛到最新。

### 判断依据

| 依据 | 说明 |
|---|---|
| `updated` 字段 | 文档最后更新时间。**注意**：无关编辑（改错别字、补图）也会刷新该字段，不能单独作为版本依据 |
| 标题版本号 | 如 `[2.7.3] 搜索页样式调整`。同功能多篇文档并存时，版本号高者优先 |
| 文档内修订记录 | 若正文含「修订记录」「更新日志」章节，读取最后一次修订内容 |

### 收敛规则

1. **按功能聚类**：把检索结果按功能归组
2. 组内按「版本号降序 → `updated` 降序」排序，取第一篇为**基准文档**
3. 若组内版本号相同但 `updated` 不同，取 `updated` 较新者，并在输出中说明存在多个版本
4. 若版本号无法比较，列出全部候选（按 `updated` 降序），标注「存在多个可能版本，已取最新」
5. 若同一份文档内部就存在多版本描述（正文前后矛盾），一并作为 E 维度问题报出

### 时效标注

输出每条跨文档结论时，必须标注依据来源：

```
依据文档：[2.7.3] 搜索页样式调整（更新于 2026-09-17）
http://note.4399doc.com/prd?note_id=2522a09e47b1a4d8701b208c&group_id=975189ff4d9aa1642cd7d1aa
```

若基准文档的 `updated` 距今超过 6 个月，追加提示：「该文档较久未更新，如线上已迭代请以现网实际为准」。

## 第 4 步：提取与比对

### 从线上文档提取

用 `mcp__note__fetch-note` 读取基准文档全文，提取：

- 功能规则（判定条件、生效范围、优先级）
- 字段与命名
- 限制值（数量、长度、时效、默认值）
- 交互结果（点击去向、状态变化）
- 权限与角色范围

### 与新 PRD 比对

逐条比对，按下表判定：

| 情况 | 严重度 |
|---|---|
| 规则结论不同，且新 PRD 未说明这是变更 | 阻塞 |
| 同一操作的结果不一致 | 阻塞 |
| 线上已有规则，新 PRD 涉及同一模块但未说明是否沿用 | 高风险 |
| 字段名、术语与线上文档不一致 | 高风险 |
| 限制值不一致且未说明 | 高风险 |
| 新 PRD 引用的线上规则，其最新版本已发生变化 | 高风险 |
| 表述接近但无法确定是否同一条规则 | 待确认（不判错） |

**判定要点**：新 PRD 主动声明「变更/升级/替代」线上规则的，不算冲突，按 A 维度（可追溯性）的正常覆盖处理。

## 链接构造

- `search-note` 直接返回 `detail_url`，可直接使用
- `fetch-note` 只返回 `id` 与 `owner_id`（即 group_id），需自行拼接：

```
http://note.4399doc.com/prd?note_id={id}&group_id={owner_id}
```

- 若链接构造失败或工具未返回必要字段，**只输出文档标题**，并注明「请自行在需求库中检索该标题查看」。不要输出拼错或猜出来的链接。

## 输出要求

E 维度条目在通用格式基础上，额外附上依据来源：

```
### [阻塞] 筛选条件的多选能力与线上 [2.7.3] 版本相反
- **位置**：新 PRD 3.2 筛选逻辑
- **依据**：[2.7.3] 搜索页样式调整（更新于 2026-09-17）
  http://note.4399doc.com/prd?note_id=2522a09e47b1a4d8701b208c&group_id=975189ff4d9aa1642cd7d1aa
- **线上规则**：高级筛选项支持多条件组合，云文档类型为多选且含「所有类型」
- **新 PRD 规则**：筛选条件为单选
- **问题**：两处结论相反，新 PRD 未说明这是对线上规则的变更
- **影响**：开发无法判断以哪份为准，可能覆盖线上已有能力
- **建议**：明确标注是否变更线上规则；若为升级，补充与旧规则的兼容说明
```

## 检索覆盖说明（必须输出）

在评审报告末尾追加本节，让用户能判断查全了没有：

```
## 检索覆盖说明
- 检索关键词：高级筛选、混合搜索、筛选条件、精卫
- 覆盖文档库：精卫-需求管理、精卫线上测试
- 命中文档：12 篇 → 剔除周报/交接文档后 5 篇
- 收敛为基准：2 篇
  - [2.7.3] 搜索页样式调整（2026-09-17）
  - [2.6.1] 全局搜索结果页（2026-05-08）
- 未覆盖：[说明未能检索到的方向，或工具调用失败的记录]
```
