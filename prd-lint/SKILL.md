# PRD Lint · 逻辑评审

## 用途

对一份 PRD 做「逻辑体检」，回答四个问题：

1. **对得上吗** — 功能方案是否真的解决了需求背景里提出的问题
2. **断了吗** — 流程、状态、分支是否完整，有没有没写完的地方
3. **打架吗** — 文档内部是否存在互相冲突的规则、数值或表述
4. **跟线上矛盾吗** — 与需求库中已有的线上功能规则是否存在冲突

前三问在单份文档内部完成校验；第四问需要检索 4399doc 需求库做跨文档比对。

## 何时使用

- 用户给出 PRD 链接或正文，要求评审、检查、体检、找问题
- 用户问「这个 PRD 逻辑有没有问题」「需求有没有冲突」「功能跟背景对得上吗」
- 用户要求核对新需求与线上已有功能规则是否冲突
- 开发评审、产品内部 review 前的预检自查

不适用：撰写 PRD、改写 PRD、纯格式或错别字校对。

## 工作流

### 第 1 步：获取文档

首选从 4399doc 读取：

- 调用 `mcp__note__fetch-note`，参数 `note_id` 为文档 ID；用户给的是链接时从 URL 中提取 ID
- 只给了文档库 ID 时，先用 `mcp__note__list-notebook` 展开目录，再配合 `mcp__note__search-note` 定位目标文档

若 MCP 不可用或读取失败，请用户直接粘贴正文。不要基于标题、目录名猜测文档内容。

### 第 2 步：结构化拆解

评审前先把文档拆成五张内部清单（不必全部输出）：

| 清单 | 内容 | 编号 |
|---|---|---|
| 问题清单 | 背景 / 目标章节提到的用户问题、痛点 | P1、P2… |
| 目标清单 | 期望达成的效果、指标 | G1、G2… |
| 功能清单 | 所有功能点、方案描述 | F1、F2… |
| 规则清单 | 业务规则、判定条件、优先级 | R1、R2… |
| 状态与分支 | 界面状态、流程分支、异常路径 | S1、S2… |

拆解质量决定评审质量。所有结论都必须能引用这些编号，避免输出泛泛而谈的判断。

### 第 3 步：文档内校验（A / B / C / D）

读取 `references/checklist.md`，按四个维度逐项校验：

- **A 可追溯性、B 逻辑完整性、C 一致性——必查**
- **D 落地质量——附加项**：仅当文档中已经写了相关内容时才校验其是否自洽。文档没有写验收标准、埋点、依赖项、非功能需求等，**不视为问题，不产出缺失类条目，也不提示补充**。

### 第 4 步：跨文档比对（E 维度）

读取 `references/cross-doc-search.md`，按其中流程检索线上需求库并做冲突检测。默认执行；用户明确要求跳过时（例如纯新增功能、无可对标文档）可省略。

这一步的四条硬约束：

- **时间必须最新** —— 线上功能规则会持续迭代，比对必须基于最新版本。同一功能存在多篇文档时，按「标题版本号降序 → 更新时间降序」收敛出基准文档
- **依据必须可溯源** —— 每条结论附上依据文档的标题、更新时间、链接。链接取自 `search-note` 返回的 `detail_url`，或由 `note_id` + `group_id` 拼接；两者都拿不到时**只输出标题**，并提示用户自行在需求库检索
- **检索不到就说明** —— 无相关文档时明确写「未检索到」，不用猜测填补，不拿无关文档凑数
- **覆盖必须交代** —— 报告末尾输出「检索覆盖说明」，列出检索关键词、覆盖的文档库、命中文档数、收敛后的基准文档

### 第 5 步：输出

按 `references/output-template.md` 的格式输出分维度问题清单。核心要求：

- 每条问题必须带**原文定位**（章节名或引用原句）；定位不到的不输出
- 每条问题标注**严重度**：阻塞 / 高风险 / 建议
- 「建议」字段要给出具体修改方向，禁止「建议完善」这类空话
- 信息不足、存在多种合理解读的，放进「待确认」分区，只描述疑点，不判定为错误
- 没有发现问题的维度写「未发现问题」，不得省略该维度

## 严重度判定

| 级别 | 判定标准 |
|---|---|
| 阻塞 | 会导致开发无法实现，或按文档实现后与需求目标相悖，或与线上规则直接矛盾 |
| 高风险 | 会导致返工、上线后出现用户可见问题，或不同人理解不一致 |
| 建议 | 表达不清、粒度不足、可读性问题，不影响正确落地 |

## 约束

- 只报告文档中**实际存在**的问题，不为凑数量制造条目；问题少不是缺陷
- 跨文档结论必须标注依据来源与更新时间；无法溯源的不输出
- 不评价需求的商业价值、优先级选择是否合理（除非文档内部自相矛盾）
- 不重写 PRD，只定位问题并给出修改方向
- 输出使用中文

## 资源

- `references/checklist.md` — A / B / C / D 四个维度的完整检查清单，含每项的判定方法与高频漏法。评审时逐项对照。
- `references/cross-doc-search.md` — E 维度跨文档比对流程：关键词提取、文档库收敛、版本收敛规则、链接构造、冲突判定表。
- `references/output-template.md` — 输出结构与单条问题写法，含严重度定义和示例。
