# PRD Lint 逻辑评审 Skill

检查 PRD 逻辑合理性与内部一致性，并对比线上需求库检测跨文档冲突。**只输出问题清单，不修改文档。**

## 功能

对一份 PRD 做「逻辑体检」，回答四个问题：

- **对得上吗** — 功能方案是否真的解决了需求背景里提出的问题
- **断了吗** — 流程、状态、分支是否完整，有没有没写完的地方
- **打架吗** — 文档内部是否存在互相冲突的规则、数值或表述
- **跟线上矛盾吗** — 与需求库中已有的线上功能规则是否冲突

## 使用场景

当用户请求以下内容时触发：

- "帮我检查这个 PRD 逻辑有没有问题"
- "这份需求有没有冲突的地方"
- "功能跟需求背景对得上吗"
- "新需求跟线上已有功能会不会打架"
- "开发评审前帮我自查一下"
- 任何 PRD 合理性校验、一致性核对的请求

## 使用方法

给出 PRD 的 4399doc 链接，或直接粘贴正文：

```
帮我 lint 一下这份 PRD：http://note.4399doc.com/prd?note_id=xxx&group_id=xxx
```

```
检查这份需求有没有逻辑冲突（随后粘贴正文）
```

## 评估维度

| 维度 | 内容 | 是否必查 |
|---|---|---|
| A 可追溯性 | 功能与需求背景的双向对应 | 必查 |
| B 逻辑完整性 | 流程闭环、状态覆盖、分支穷尽、角色权限 | 必查 |
| C 一致性 | 文档内部规则、术语、数值、口径冲突 | 必查 |
| D 落地质量 | 验收标准、埋点、依赖项、非功能需求 | 附加项（文档未写则不评估） |
| E 跨文档一致性 | 与线上需求库已有规则的冲突 | 默认执行 |

## 工作流程

1. **获取文档** — 通过 4399doc 链接（note MCP）读取，或接收粘贴正文
2. **结构化拆解** — 拆成问题、目标、功能、规则、状态五张清单
3. **文档内校验** — 按 A / B / C / D 四个维度逐项对照 `references/checklist.md`
4. **跨文档比对** — 检索线上需求库，按版本收敛出基准文档后逐条比对规则
5. **输出清单** — 按维度分组，每条标注严重度、原文定位与依据来源

## 严重度分级

| 级别 | 含义 |
|---|---|
| 阻塞 | 会导致开发无法实现、按文档实现后与需求目标相悖，或与线上规则直接矛盾 |
| 高风险 | 会导致返工、上线后出现用户可见问题，或不同人理解不一致 |
| 建议 | 表达不清、粒度不足、可读性问题，不影响正确落地 |

## 输出示例

```
# PRD Lint｜高级筛选与混合搜索

检查项 34 项 · 发现问题 7 项（阻塞 2 / 高风险 3 / 建议 2）

## C. 一致性
### [阻塞] 筛选规则与搜索规则的命中优先级缺失

- 位置：3.2 筛选逻辑 / 4.1 混合搜索
- 问题：两处规则均可能作用于同一结果集，未定义二者同时生效时谁先执行
- 建议：补充仲裁规则，或明确二者互斥

## E. 跨文档一致性
### [高风险] 筛选条件的多选能力与线上 [2.7.3] 版本相反

- 依据：[2.7.3] 搜索页样式调整（更新于 2026-09-17）
  http://note.4399doc.com/prd?note_id=2522a09e47b1a4d8701b208c&group_id=975189ff4d9aa1642cd7d1aa
- 线上规则：云文档类型为多选且含「所有类型」
- 新 PRD 规则：筛选条件为单选
```

## 设计要点

- **D 维度为附加项** —— 验收标准、埋点、依赖项不一定每份文档都有，缺失时不视为问题
- **E 维度取最新版本** —— 线上规则会持续迭代，按「标题版本号降序 → 更新时间降序」收敛基准文档
- **依据必须可溯源** —— E 维度每条结论附文档标题、更新时间与链接；拿不到链接时只输出标题
- **区分冲突与变更** —— 新 PRD 主动声明「变更 / 升级 / 替代」线上规则的不算冲突
